# 原生导航与全端图标

本次以 H5 的层级、返回上下文与减弱动态效果规则为基准。iOS 继续使用 NavigationStack、TabView、系统 sheet 和原生侧滑；不在原生页面上再叠加一层网页式转场。

| Before | After | Why |
| --- | --- | --- |
| 根页观察器在生命周期回调里直接修改 UITabBar.isHidden | 根页/子页使用原生 tab bar 可见性 API；完成或取消转场后按实际导航栈校正 | 避免侧滑取消后底栏提前出现；iOS 18+ 使用系统显隐动画 |
| 大师端分段内容每次出现时重放错峰淡入 | 去掉重复入场，保留按压、数值和选择反馈 | 不与原生 push/pop 叠加 |
| 列表刷新直接替换整屏加载态 | 首次加载占位；刷新保留已有列表，取消请求不清空数据 | 保留滚动和筛选上下文 |
| 未知网页图标名直接传给 SF Symbols | 信仰入口使用明确的原生符号映射 | 避免系统无法渲染导致空图标 |
| 启动屏空白、工作台缺少品牌署名 | 两款 App 的动态启动标识、主题背景、工作台品牌与加载标识 | 保持各角色身份清晰 |
| 管理页面只有装饰色条 | 共用语义图标，标题文本仍保留 | 方便识别页面类型；图标不重复朗读 |
| 管理台 favicon 不跟随应用外观 | 同步浅深色图标和浏览器主题色 | 浏览器入口与页面一致 |

功能图标采用 24 单位圆角描边，常用显示尺寸 20–24px。iOS 使用 SF Symbols，保留系统适配；不以图标替代按钮标签。品牌沿用 packages/brand 的六角色体系；功能图标、头像、内容图不冒用品牌标识。

信众与大师各 Tab 持有独立 NavigationPath；会话切换由现有根视图身份隔离。目录数据保存在当前 ViewModel 内，不创建跨账号私人数据缓存。下拉刷新仍会请求最新目录。

## 验证

- iOS：两款 App 模拟器构建；信众端目录进入、返回、取消侧滑、标签切换、游客 DIY；动态品牌资源和 SF Symbols 解析检查。
- Web：各应用 build，管理主题测试和既有认证/导航回归；移动浅深色、主导航、品牌入口和生产静态资源验收。
- 每次运行的结果及发布版本记录在工作区 artifacts/native-brand-20260927/VERIFICATION.md。没有真机测试结果时不宣称真机帧率或安装完成。
